# 作业批改统计程序

这是一个面向教师的本地中文终端工具，用于连续多周保存作业批改结果。程序按学生录入错题编号，可将一道大题划分为多个小问，并以小问为最小计分和统计单位，自动计算答对计分单位数和等级。所有已确认的数据立即写入 SQLite 事务；退出程序或关闭电脑后可重新打开。

程序是单用户离线工具，不包含网络服务、账号、学生姓名或图形界面。数据库里保存的是作业配置、题目结构、稳定的录入顺序和错题集合；答对数量、等级及统计在读取时计算，避免派生数据互相矛盾。

## 功能

- 新建、列出、重新打开和删除多份作业。
- 在新建、选择作业、新增、修改或删除学生记录时输入 `-1`，可取消当前操作并返回上一界面。
- 所有确认操作统一输入 `y` 或 `n`（大小写均可），无需切换中文输入法。
- 用空格、英文逗号或两者混合输入错题；回车或“无”表示全对。
- 新建作业时可用 `2=3 5=2` 声明小问；错题可精确输入为 `2.1`，也可输入 `2` 快速表示该大题全部小问。
- 对输入范围、重复题号、非整数、小数和负数给出中文错误并重新询问。
- 达到总学生数后阻止继续新增。
- 每次新增或修改成功后立即输出该学生的答对计分单位数和等第。
- 打开作业后，可按相同的“倒数第几个”规则定位并修改或删除学生记录；删除前会展示记录并要求再次确认。
- 修改或删除记录不会改变其他学生的原始录入序号。
- 按大题分组显示逐小问正确率和全题正确率，并显示各等级人数/百分比和总体完成率；零份记录时安全显示“暂无数据”。
- SQLite 外键、5 秒 busy timeout、WAL 模式、版本化迁移和事务提交。

## 依赖

- 支持 C++20 的编译器：GCC 10+、Clang 12+ 或 Visual Studio 2022。
- CMake 3.20 或更新版本。
- SQLite3 运行库和开发头文件。
- 可选：Ninja 和 `clang-format`（格式检查需要）。

### Linux

Ubuntu/Debian：

```sh
sudo apt-get update
sudo apt-get install build-essential cmake libsqlite3-dev clang-format ninja-build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Fedora 可安装 `gcc-c++ cmake sqlite-devel clang-tools-extra ninja-build`；Arch Linux 可安装 `base-devel cmake sqlite clang ninja`。

### macOS

先安装 Xcode Command Line Tools，再用 Homebrew 安装依赖：

```sh
xcode-select --install
brew install cmake sqlite clang-format ninja
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH="$(brew --prefix sqlite)"
cmake --build build
ctest --test-dir build --output-on-failure
```

### Windows

可使用 Visual Studio 2022 和 vcpkg。在“Developer PowerShell for VS 2022”中：

```powershell
vcpkg install sqlite3:x64-windows
cmake -S . -B build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/path/to/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

将 `C:/path/to/vcpkg` 换成实际目录。也可以使用包含 SQLite3 开发包的 MSYS2/MinGW 环境。

## 运行

Linux/macOS：

```sh
./build/homework-grader
./build/homework-grader --db ./test-data/homework.db
```

使用 Visual Studio 多配置生成器时，Windows 可执行文件通常位于：

```powershell
.\build\Debug\homework-grader.exe
.\build\Debug\homework-grader.exe --db .\test-data\homework.db
```

数据库路径优先级为 `--db <路径>`、环境变量 `HOMEWORK_GRADER_DB`、系统默认位置。程序自动创建数据库父目录。

默认位置：

- Windows：`%LOCALAPPDATA%/homework-grader/homework.db`
- macOS：`~/Library/Application Support/homework-grader/homework.db`
- Linux：`$XDG_DATA_HOME/homework-grader/homework.db`
- Linux 未设置 `XDG_DATA_HOME`：`~/.local/share/homework-grader/homework.db`

## 大题与小问输入

新建作业时先输入大题数，再用一行可选声明指出含小问的大题。`2=3 5=2` 表示第 2 题有三个小问、第 5 题有两个小问；没有小问时直接回车。小问数至少为 2，同一道大题不能重复声明。系统会先显示解析后的结构和计分单位总数，再要求设置等级下限。

没有小问的大题本身是一个计分单位；含小问的大题中，每个小问各是一个计分单位，大题本身不重复计分。例如五道大题采用 `2=3 5=2` 时，共有八个计分单位：

```text
1
2.1 2.2 2.3
3
4
5.1 5.2
```

录入错题时可以输入 `1 2.1 2.3 4`。对含小问的大题直接输入大题号会展开为全部小问，例如输入 `2` 等价于 `2.1 2.2 2.3`；确认前会显示为 `2（全部小问）`。不能同时输入 `2` 和 `2.1`，也不能重复输入同一小问。当前只支持数字大题号和点号分隔的数字小问，不支持范围、字母标签、权重或部分得分。

## 返回上一界面

在新建作业的任一输入项、选择要打开或删除的作业、新增学生记录、选择或重新输入待修改记录、选择待删除记录时，可以输入 `-1` 取消当前操作并返回所属菜单。作业菜单也可以输入 `-1` 返回作业列表。

已有的返回方式继续有效：选择作业时可以输入 `0`，作业菜单可以选择 `5`，确认提示可以输入 `n`。主菜单没有上一层，因此不接受 `-1`，仍应选择 `4` 退出程序；`y/n` 确认提示也只接受 `y` 或 `n`。

从主菜单删除整个作业时，程序会先列出作业及录入进度，再显示目标作业和受影响的记录数。输入 `y` 后，作业、学生记录和错题数据会在同一个 SQLite 事务中永久删除；输入 `0` 取消选择，或在确认时输入 `n`，都不会改变数据。如果以后仍可能用到这份作业，请先按下文方法备份数据库。

## 统计口径

没有小问的大题计为一个计分单位；含小问的大题中每个小问分别计分。答对计分单位数等于计分单位总数减去错误计分单位数，等级由这个答对数量决定。

每个计分单位的正确率和等级分布只以当前作业已经录入的学生为样本，而不是计划中的总学生数。小问正确率为“该小问答对人数 ÷ 已录入人数”。含小问大题的“全题正确”要求该学生所有小问均正确，它只用于统计展示，不额外参与计分。等级百分比为“该等级人数 ÷ 已录入人数”，作业完成率单独按“已录入人数 ÷ 总学生数”计算。界面统一显示两位小数；尚无记录时题目和等级百分比显示“暂无数据”，完成率仍为 `0.00%`。

## 数据库升级

程序会在事务中把 schema version 1 数据库自动升级到 version 2。旧作业的每一道题会转换成一项“无小问”的计分单位，原有错题、等级口径和录入顺序保持不变。version 2 使用结构化的大题号和小问号保存计分单位，错题通过外键引用计分单位；数据库不保存答对数量、等级或正确率等派生结果。

## 安全备份

最稳妥的简单方法是先正常退出程序，再复制 `homework.db` 到备份位置。程序使用 WAL 模式；如果必须在程序运行时进行文件级备份，应同时复制同目录下可能存在的 `homework.db-wal` 和 `homework.db-shm`，不要只复制主文件。更推荐在退出后备份，或使用 SQLite 官方命令行的 `.backup` 命令：

```sh
sqlite3 /path/to/homework.db ".backup '/safe/place/homework-backup.db'"
```

恢复前保留当前数据库副本，确认程序已退出，再替换主数据库。数据库包含教师的实际作业数据，仓库的 `.gitignore` 会阻止常见 SQLite 文件进入 Git；仍请在提交前检查 `git status`。
